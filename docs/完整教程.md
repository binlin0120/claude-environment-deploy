### 先分清楚谁来做

准备一台能正常使用 Windows、运行 Codex 并联网的电脑。检查、下载、安装、配置、排错和测试尽量由 Codex 操作；你负责选择要用的服务、按需购买和付款，以及登录、验证码、身份核验、Windows 许可和必要的系统授权。具体分工见 [首页说明](../README.md#codex-做什么你需要做什么)。

当前包有五个辅助入口，能检查电脑、创建一台尚未安装 Windows 的关机虚拟机、检查当前环境的新连接出口、只读核对 Windows 来宾的配置和实际防火墙状态，以及只读关联主机转发路径；另有一个共享的核心接口读取帮助文件。只读检查缺少证据时会报告待核对，不会自动修复。之后的 Windows 安装、网络和浏览器配置，仍要由 Codex 结合现场权限与操作工具继续完成。它无法操作的界面，需要你按说明点击；这份草稿还没有做到从新电脑到 Claude 可用的全程自动安装。

购买入口见 [工具和购买入口](../02_采购清单与工具入口.md)。**这些网站只是参考推荐，不是指定商家，也不是每一项都要买。已有服务可以先检查复用，也可以自己找其他供应商。**把所选服务的官网和公开教程交给 Codex，它再核对怎么配置；先确定缺什么，再购买，不用提前把所有东西买齐。

这里的“部署 Claude”，指安装官方客户端、命令行工具以及可选的独立电脑环境。Claude 的模型在服务商处运行；本教程不会把 Claude 模型安装到自己的 VPS（租来的云服务器）上。VPS、住宅 IP、指纹浏览器都不是使用 Claude 的官方必需条件，不能保证账号可用、稳定或不被停用。

电脑检查、虚拟机和通用软件配置可以先做，不需要先回答自己住在哪个国家。**Claude 的登录和服务使用按其当前官方支持条件单独处理；代理出口不会改变实际所在地或证明账号资格。** 使用前由本人核对，不符合时说明 Claude 应用阶段未完成，继续不依赖它的已授权环境配置，不能因此把整个电脑配置项目停掉。若某项网络改造的唯一目的只是隐藏实际所在地、绕过官方服务或账号限制，不执行那一项网络改造。

本版分为 Windows x64＋Hyper-V 和 [Mac 虚拟机部署](../skills/claude-environment-deploy/references/Mac部署流程.md) 两条路线。Mac 按 Apple 芯片或 Intel 选择 Windows ARM64／x64；用 Fusion 或用户已选软件，不运行 Hyper-V 脚本。Mac 分支依据官方资料新增，Windows ARM 中 AdsPower 尚需实测，不能把本包称作已验证的跨平台一键安装器。软件签名核对失败属于独立问题，要核对具体错误和官方来源，再决定如何处理，不能关闭校验来继续安装。

当前为修正版9（2026-10-31）：补强只读网络证据、订阅对账及持久化复核，未在新电脑跑通完整流程；历史验证仅代表当时机器与版本。

## 1. 先选适合自己的路线

| 路线 | 适合谁 | 需要准备 |
| --- | --- | --- |
| A：Windows 本机安装官方 Claude / Claude Code | 只想正常聊天或让 Claude 帮忙写代码 | 符合官方要求的系统、网络和本人账号 |
| B：完整隔离方案，Hyper-V＋AdsPower 专用环境 | 配置虚拟机中的 Claude 网页及所选桌面端 | 支持 Hyper-V 的电脑、合法 Windows、来宾网络、AdsPower 与本人账号 |
| C：B 路线所需的独立网络配置 | 现有网络不能满足已选隔离要求，需要额外配置 | 自己有权使用的网络服务、可恢复的配置和额外验收；不一定需要新购买 |

Hyper-V 是 Windows 自带的虚拟机功能，虚拟机会像另一台电脑一样运行 Windows。路线 A 是用户明确选择本机使用时的分支，本机仍可选择 AdsPower 或普通浏览器；不能把“本机”自动当作不要指纹浏览器。**按本包完整教程部署时采用 B，AdsPower 的配置和验收是该路线的组成部分，不能跳过。** 指纹浏览器会管理独立的浏览器配置与会话；它不是 Claude 官方使用前提，修改指纹也不是账号安全保证。

完整方案使用 Windows 来宾、Clash Verge Rev / Mihomo、AdsPower 和所选官方 Claude；Windows 主机用 Hyper-V，Mac 主机用其已选虚拟机软件。Mihomo 是处理代理连接的核心程序，Clash Verge Rev 是管理它的图形界面。资源、版本和网络参数应按实际电脑配置，不照搬别人的固定值。

## 2. 准备电脑、账号和预算

先看 [适用电脑与操作前检查](../skills/claude-environment-deploy/references/适用电脑与操作前检查.md)。里面写了我们的主机配置，也逐项说明：什么条件能继续、要先解决什么、哪些情况不建议使用。教程供参考，其他电脑的完整部署待验证；一键执行可能改动系统或网络、需要重启、影响已有软件，先保存工作和备份，再让 Codex 说明计划。

1. 核对所选 Claude 产品的当前系统要求；只有选择 B 完整隔离路线时，才另外检查 Hyper-V。家庭版若要走这条 Hyper-V 路线，先准备有效的专业版升级许可，没有许可再购买，完成版本升级和激活后再检查 Hyper-V。已有适用专业版密钥的可以按官方流程使用；付款、密钥输入和必要重启由本人配合。操作入口和 [微软官方升级说明](https://support.microsoft.com/en-us/windows/upgrade-windows-home-to-windows-pro-ef34d520-e73f-3198-c525-d1a218cc2818) 已放入检查表。专业版也要硬件支持虚拟化且已开启，不能只看激活成功。
2. 选虚拟机路线时，主机 16 GB 内存可作为轻量使用的评估起点；如果日常软件已经占满内存，就不适合再分配 4～8 GB 给虚拟机。磁盘应容纳镜像、虚拟硬盘、更新和备份，不能只看新建虚拟磁盘的最小占用。
3. 当时我们分配了 4 个虚拟处理器、4～8 GB 动态内存，以及最大 80 GB 的动态虚拟硬盘。你的电脑不必照抄，按剩余资源调整；磁盘还要给后续更新和软件留空间。
4. 准备本人官方账号。服务订阅、Claude Code 的可用认证及付费方式应以账户实际页面和当期官方说明为准，不能把网页登录成功当成命令行额度已包含。
5. 算清软件订阅、Windows 虚拟机许可、可选浏览器套餐、可选 VPS / 网络服务、续费和维护时间。主机 Windows 已激活，不代表另一份虚拟机 Windows 自动获得许可。

Windows 主机路线的项目文件统一放在主机 D:\Codex；Mac 主机的目录先按 Mac 流程由本人确认。以下 D 盘前提只针对 Windows。没有可用 D 盘，不建议使用这套包，不为此重新分区或改存 C 盘。Windows 功能、用户设置及某些安装器仍可能必须写主机 C 盘。Agent 必须先列出具体位置和必要性，请本人同意后才做；不承诺“零 C 盘写入”。虚拟机内部的 C 盘位于主机 D 盘的 VHDX 文件中，VHDX 就是虚拟硬盘文件，两者要分清。

可以先在 PowerShell 中执行下面的只读检查；输出只在窗口查看，不要把带设备身份的信息直接公开：

~~~powershell
Get-ComputerInfo -Property WindowsProductName,WindowsVersion,OsArchitecture,HyperVisorPresent,CsTotalPhysicalMemory
Get-Volume -DriveLetter D | Select-Object DriveLetter,SizeRemaining,Size
Get-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V-All
~~~

最后一条可能需要管理员窗口。若前提不满足，先选路线 A 或更换合适设备，不边猜边安装。

## 3. 先给 Codex 明确任务和权限

把仓库交给 Codex 后，让它先检查电脑，再列出安装步骤和要改的设置。检查、下载、配置和测试交给它；登录、验证码、付款、条款和必要授权由你完成；Windows 能用命令或现有工具配置的设置由 Codex 完成，不笼统把首次设置全交回本人。需要重启电脑、修改本机网络、发起付费调用或扩大文件共享范围时，先让它说明影响，等你同意再做。

不要把密码、Cookie、订阅链接、代理凭据、SSH 私钥、产品密钥或 OAuth 回调链接粘贴进聊天。OAuth 是网站向应用授予登录权限的流程，其回调参数也可能含敏感信息。需要登录时，Agent 停在登录页面，你在自己的电脑上输入；完成后只确认是否已登录。

仓库附带五个 PowerShell 辅助入口和一个共享帮助文件，位于 [Skill 的 scripts 目录](../skills/claude-environment-deploy/scripts)，兼容 Windows PowerShell 5.1 和 PowerShell 7：Test-ClaudePrerequisites.ps1 检查 Windows 主机前提；New-ClaudeVM.ps1 生成 Hyper-V 虚拟机创建计划，只有明确加上 -Apply 才创建；Test-ClaudeEgress.ps1 在受保护的 Windows 来宾核对指定本机代理，须提供 -EvidencePath、-ProxyPort 和 -ExpectedExitIp，通过才默认发 3 次 Claude 检测请求，并逐条记录；Test-ClaudeGuestNetwork.ps1 在 Windows 来宾只读核对多个相关节点、订阅快照龄、持久配置、保存与当次核心状态、DNS 和实际生效防火墙及疑似 Block 冲突；可选 -EvidencePath 读取本地私有证据，-ReadCoreApi 明确启用现有本机核心接口只读查询。缺证据写未知，已知错误照常报告。Test-ClaudeHostPath.ps1 在实际 Windows 主机只读关联近期转发日志，也可用这两个参数；共享 Read-ClaudeCoreApi.ps1 不单独部署。具体证据与限制见 [来宾网络一致性检查](../skills/claude-environment-deploy/references/来宾网络一致性检查.md)。

先读脚本和参数再执行，不能把“脚本存在”当作“部署已通过”。主机运行的检查不能证明来宾状态；这些网络检查也不能代替指定 AdsPower 窗口检测、实际停核心、恢复和重启验收。预期地址由 Agent 从本机受控配置读取后通过内存变量传入，不把真实值写在示例、聊天、终端历史或公开记录里。可以直接让 Codex 读取仓库中的 SKILL.md，不要求先把 Skill 全局安装到主机 C 盘。

## 4. 路线 A：先让官方工具正常运行

1. 从官方 Claude 下载页进入 Windows 安装流程。Claude Code 则按当前官方安装说明选择 Windows 支持的安装方式；先查是否已安装，避免重复部署。
2. 下载到 D:\Codex 下的安装包目录。Agent 记录版本、原始来源、下载时间、SHA-256 和数字签名。SHA-256 是文件内容的校验指纹；自己计算它只能记录一致性，只有与可信官方清单对上才能进一步核对来源。
3. 对 Windows 可执行安装包可使用以下只读命令，路径换成实际文件。已有签名验证失败、签名者异常或可信官方清单摘要不符时停止安装。没有 Windows 签名的开源包，按对应参考核对官方 HTTPS 固定版本来源与可信官方摘要或对应分离签名，并明确实际证据；不能把没有签名说成签名验证成功，也不凭自行计算的摘要证明来源。来源无法核实时停在依赖点，不关闭系统保护继续。

~~~powershell
Get-FileHash -LiteralPath 'D:\Codex\下载\实际安装包.exe' -Algorithm SHA256
Get-AuthenticodeSignature -LiteralPath 'D:\Codex\下载\实际安装包.exe' |
    Select-Object Status,@{Name='Signer';Expression={$_.SignerCertificate.Subject}}
~~~

4. 若官网下载跳转失败，可以检查微软维护的 winget-pkgs 等公共软件清单是否指向发行方的固定版本包。清单是核对线索，不能代替安装包签名，也不要把第三方重打包当官方包。
5. 完成安装并记录实际程序版本。涉及网页时，本机＋AdsPower 也必须先保存并打开目标环境，在同一窗口打开 https://ip.net.coffee/claude/，按第 5.2 节完成本次检测、确认无待处理异常后，才打开 Claude 网页并由本人登录；明确选择普通浏览器时在其实际窗口做同一检测，不为检测额外装 AdsPower。所选桌面端随后启动并单独验收；仅选 Code 且无网页时不扩大范围。不迁移其他电脑的 Cookie，不读取令牌文件。
6. 用新对话做两轮不含隐私的测试，例如“请记住测试编号 4827”后问“刚才的编号是什么”。网页能打开、欢迎页出现或第一次回答成功，都不等于连续聊天通过。
7. Claude Code 先检查命令是否可运行和认证状态；真正发模型请求可能涉及费用或额度。Agent 应在调用前说明测试内容、次数及预算上限，获准后再测。不要仅凭输出中的费用字段断言实际扣款，账单由本人核对。

如果这条路线已满足需求，到这里即可；无需为教程完整而额外购买 VPS 或 IP。

## 5. 路线 B：建立独立 Windows 虚拟机

1. 保存工作，检查 Hyper-V 是否已启用。未启用时先说明 Windows 功能变更及可能的主机重启，由本人决定时间；不要自动重启正在工作的电脑。
2. 从微软官方渠道获取适用的 Windows ISO，ISO 就是系统安装镜像。核对版本、架构、许可和可信校验信息，不公开或分享产品密钥。
3. 在 Hyper-V 管理器中创建“第二代”虚拟机。虚拟机配置、硬盘和镜像位置设在 D:\Codex 下的独立目录；按机器余量设置内存、处理器和磁盘。按当前 Windows 要求启用安全启动及虚拟 TPM，TPM 是系统使用的安全芯片功能。
4. 网络先使用已存在且合适的虚拟交换机。不要为方便把主机网卡改成桥接，不擅自新增外部交换机或改主机 DNS、路由、代理和防火墙。主机能联网不代表虚拟机拥有同样出口。
5. 挂载 ISO、启动安装。Agent 完成工具能够执行的首次系统设置，许可确认和本人登录交给你；不要使用绕过账号资格或系统要求的脚本。系统更新及来宾重启应安排在允许的时段。
6. 进入桌面后，记录系统版本和磁盘位置。来宾 C 盘可以保存系统和应用，只要虚拟硬盘仍位于主机 D 盘。按后文先完成来宾网络和 AdsPower 配置，保存并打开目标环境，在同一窗口先完成 https://ip.net.coffee/claude/ 本次检测，确认无待处理异常才打开 Claude 网页并本人登录，随后打开所选桌面端。可以提前下载安装包，首次使用按这个顺序进行。
7. 默认不共享主机整块磁盘、浏览器资料、密码库、打印机或其他设备。需要复制时优先传一个明确文件，并核对 SHA-256。开启剪贴板、麦克风或文件重定向都会增加两台电脑之间的信息通道，应按实际需要选择。

关键变更前保存配置和必要数据。Hyper-V 检查点可帮助回退某些变更，但不是独立备份，也不保证账号登录状态或外部服务状态一起回到过去。

### 5.0 先配来宾系统，再配 Clash 网络

进入桌面后，Agent 必须执行 [来宾 Windows 语言与时间](../skills/claude-environment-deploy/references/来宾Windows语言与时间.md)，按已选目标配置并回读系统语言、区域和日期时间格式、Windows 时区以及准确校时。它们与 AdsPower 浏览器语言时区分别验收；没有必须全英文或统一美国城市时区的前提。

接着执行 [Clash 与来宾网络配置](../skills/claude-environment-deploy/references/Clash与来宾网络配置.md)。在 Windows 来宾安装或复用匹配架构的官方 Clash Verge Rev，导入已选服务，配好实际出口与必要串联、TUN/DNS/IPv6、出站保护和配置持久化。Mac 也在 Windows 来宾执行，主机 DMG 不能代替。网络就绪后再做 AdsPower 联网和 ARM 兼容性检查，最后完成代理中断、恢复和来宾重启复验。

### 5.1 配好 AdsPower，不能只装软件

完整操作见随 Skill 一起分发的 [AdsPower 配置与验收](../skills/claude-environment-deploy/references/AdsPower配置与验收.md)。按下面的顺序实施；如来宾网络还未就绪，先完成第 6 节，再继续本节的联网验收。

1. 在目标来宾内检查 AdsPower。主机已装不代表虚拟电脑里也有；来宾已经安装时只跳过重复安装，仍要核对版本、本人登录、Claude 专用环境及其设置。没有时再从官方来源下载、验签、安装，商业安装包不附在公开仓库里。
2. 本人先登录 AdsPower 账号；这是浏览器管理软件自己的账号，与 Claude 登录分开记录。账号或套餐的具体权限按当前页面核对，不能从旧记录猜。
3. 只建立或复用一个固定的 Claude 专用环境。这里的“环境”就是独立保存浏览器设置和会话的资料夹。以后重开、排错和重启都使用它，不反复新建环境、不清会话、不复制其他电脑的 Cookie。
4. 根据现场选择让该环境连接来宾内代理，或通过来宾的 TUN 网络接管；检查实际流量，不随意叠加。来宾里的 127.0.0.1 指来宾自己，端口也要从当前配置核对，不能照抄主机。
5. 设置并核对 WebRTC 禁用、时区和语言与所选网络环境一致、浏览器内核与 UA 主版本一致。UA 就是浏览器向网站自报的版本信息。按当前版本设置页保存，再在该环境里的网页检查真实结果；不把地区、具体时区或旧内核版本写死。界面中文翻译与网页请求语言分别处理，不因需要中文显示就无意改变其他设置。
6. WebRTC 是浏览器的实时通信功能。设置写着禁用，还要测是否暴露地址；接口仍存在不等于地址泄漏。DNS 域名解析、IPv6 网络地址、时区和语言也分别测。没有采用的画布、字体等指纹选项保持默认或现有值，不为了“更安全”随意随机化。
7. 关闭并重新打开同一环境，回读设置并做新的网络请求，确认配置保存、网络路径一致。公开记录仅写匿名代号和结果，不上传环境目录、完整配置、账号标识或登录数据。
8. 保存指定环境并从 AdsPower 管理界面启动，确认实际弹出的窗口与它对应。必须先在同一个窗口打开 https://ip.net.coffee/claude/，按第 5.2 节完成本次检测并确认无待处理异常，再打开 Claude 网页。若检测页或 Claude 页面开在普通浏览器，记为“指定环境步骤未完成”，保留原有标签页和账号，不退出、不清数据，再回到正确环境处理。页面网址相同不等于使用了同一个浏览器环境。

我们当时使用的免费环境不能调用 Local API，也就是让程序控制 AdsPower 的本机接口。现在能不能用，要核对当前账号权限、连接状态和版本，不能只看旧套餐说法。接口不可用时，有桌面操作工具就用界面；两种都没有时，给出本人点击步骤，不自动升级付费或换普通浏览器。模型繁忙或容量不足也不是更换环境的理由，错误与浏览器身份分开排查。

### 5.2 同窗口先检测，再打开和登录 Claude，最后打开所选桌面端

这是本套流程的必做前置步骤。保存并打开目标 AdsPower 固定环境后，必须在同一个实际窗口先打开 [Claude 网络检测页](https://ip.net.coffee/claude/)，等待本次检测完成；目视核对当前 IP（网站看到的网络出口地址）、国家地区、网络属性，以及 DNS（域名解析）、WebRTC（浏览器实时通信）和时区等可见结果，确认与预期配置一致、无待处理异常后，再打开 Claude 网页并本人登录。首次部署、日常使用、重开环境、恢复网络、重启或更新后都重新检测；已登录的继续使用原环境，不必退出重登。

关键出口结果缺失、检测页打不开或超时、有待处理异常，或无法控制和确认目标窗口时，暂停依赖它的 Claude 打开与使用步骤，写清卡点及本人从哪里打开网址、核对哪些结果；不静默跳过、不换普通浏览器、不自行换检测方式，其他独立且已获授权的工作继续。DNS 或 WebRTC 无结果不等于没有泄漏，须说明覆盖限制并核对原因。评分和绿色提示只是参考，不要求所有评分绿色，不能据此证明账号或桌面端可用。只记录检测时间、匿名环境代号、检测完成状态和非敏感结论，不保存真实 IP 或带真实地址的截图。

另有 claude-switcher 可供感兴趣的人了解，我们没有在这套环境里安装使用。它的 Windows 看守在代理状态异常时关闭 Claude 桌面进程，不能保护 AdsPower 网页或代替防火墙；安装还可能修改系统和代理配置。功能、限制与上游入口见 [使用前检测与可选防护](../skills/claude-environment-deploy/references/使用前检测与可选防护.md)，自行判断，不作为默认安装步骤。

**操作顺序：来宾网络检查 → AdsPower 固定环境配置、保存并打开 → 同一窗口先打开 https://ip.net.coffee/claude/，完成本次检测且无待处理异常 → 才打开 Claude 网页并本人登录 → 再打开所选桌面端并单独验收。**

先在固定的 AdsPower 专用窗口完成上述指定检测，确认本次无待处理异常，才在同一窗口打开官方 Claude，交给本人完成登录；Agent 仅检查已登录界面和新测试对话。确认这一步完成，再打开本次选中的来宾桌面端 Claude。如果桌面端提示登录，由本人按当前版本官方流程完成；不额外要求把它的授权链接转进 AdsPower，不擅自修改全局默认浏览器。

授权页面地址可能含一次性参数，不发到聊天、不写进报告、不截图留存，不改回调或校验参数；不能通过复制 Cookie 把浏览器登录移到桌面端。具体授权衔接以当前官方版本为准，无法完成时清楚停在该项，不重置已可用的浏览器环境。

同一 AdsPower 窗口先完成指定检测、再打开和登录 Claude 网页、随后打开所选桌面端，是这套方案采用的顺序。桌面端仍要单独检查登录、网络和两轮对话，因为它不会自动继承 AdsPower 的设置。这个顺序不是所有 Claude 用户都必须照做的要求；我们也还没测完桌面端的完整对话。

### 5.3 同一环境的恢复与验收

继续使用同一个 AdsPower 环境，按第 7 节逐项检查网络和 Claude 网页对话。关闭重开、网络恢复、虚拟机重启或更新后，先检查原环境和设置是否保留，再在同一窗口重新完成第 5.2 节指定检测，确认无待处理异常才继续 Claude；不用旧结果替代。需要重新登录时由你操作。所选桌面端单独检查登录和两轮对话。代理停止、恢复、虚拟机重启及更新后的测试，安排在你不用虚拟机时进行；没测的项目就写“未测”。

## 6. 路线 C：只有确有需求，才部署独立网络

### 6.1 用自建 VPS 做最终出口

如果已经有可用的自建 VPS，可以让选定应用的流量经它访问网站。示意路径是「应用 → 本机代理客户端 → 自己的 VPS → 网站」，以应用里查到的公网 IP 为准。已有 VPS 路线能满足需求时，可以直接使用已有服务。若明确选了「VPS 中转 → 另一个最终出口」，网站看到的是最后一段的 IP。选定哪条路，先在本机记下这条路应显示的出口，再开始改配置。

**我实际用过的路线**是 Windows 主机上的 Chrome 和 AdsPower，经 Clash Verge Rev 连接自建 VPS。客户端用 VLESS（一种代理连接协议），服务器运行 sing-box（接收并转发连接的开源软件）。2026-11-10 用两个浏览器分别发起新请求，确认仍是原自建 VPS 的公网出口。这一轮测的是 Windows 主机浏览器。Mac 和虚拟机要各自在目标应用里验一次，下载速度当时也有波动。[sing-box 官方 VLESS 文档](https://sing-box.sagernet.org/zh/configuration/inbound/vless/)

1. 确认要改的是主机还是虚拟机，并在那台系统备份当前配置，留好原节点和回退办法。租来的 VPS 有自己的公网出口。需要判断它是否为住宅网络时，要另核对供应商和公网 IP 归属。
2. 在目标系统的 Clash Verge Rev 导入已有自建节点，把需要走该出口的应用交给对应规则。服务器地址、协议、端口和凭据按自己的部署填写，凭据只在本机保存。
3. 分别在目标 Chrome、AdsPower 或其他实际使用的应用里新开请求，核对显示的公网 IP，并查看代理客户端连接日志，确认该应用命中了自建节点。换到虚拟机或重开客户端后，再在对应系统复验。若结果不符，按备份恢复后排查。[虚拟机内的配置与验收](../skills/claude-environment-deploy/references/Clash与来宾网络配置.md#3-由-agent-导入已有代理并落实链路)

#### 自建 VPS 卡顿怎么查

要照着执行，打开 [自建 VPS 排查操作参考](自建VPS排查操作参考.md)，里面有分段测速命令、Clash 规则示例、BBR 实际连接检查和回退步骤。

1. **先固定原出口，再测速度。** 在实际使用的浏览器新开请求，记下公网 IP、命中的代理节点、网页耗时和下载完成情况。每轮用同一个文件、同一个节点、同一台客户端，记录失败和收到的字节数。换到另一个节点变快，只说明另一条路快。网页、文件下载和登录后操作分别测，打开邮箱登录页只能算登录页测试。
2. **把两段路拆开测。** 同一时段，在 VPS 上直接下载测试文件，再在电脑上通过现用代理下载同一文件。顺手检查 VPS 的处理器负载、可用内存和代理服务状态。2026-11-10 的实测中，VPS 直接下载约 1 MB 用了约 0.24 秒，电脑通过代理下载同一文件，15 秒超时，只收到约 316 KB。结合多条连接重复发送数据、发送速度受限，当时优先查电脑到 VPS 的代理链路。具体在哪一段卡仍未定位，连接中重复发送的字节比例也不能直接当作丢包率。
3. **网页慢，先看目标浏览器的连接日志。** 当时原 VPS 能转发部分 UDP 流量，但网页用的 QUIC（一种通过 UDP 443 端口传输网页的协议）出现只发不回。我们只对目标浏览器限制这类请求，让它试走 TCP（浏览器另一种常用连接方式）。Chrome 的规则命中已确认，AdsPower 的专用 UDP 规则未独立确认。两个浏览器的公网 IP 均与原 VPS 一致，页面和下载仍有波动。其他电脑遇到类似问题，先核对实际进程、请求去向和是否意外直连，再决定是否改规则。[Mihomo 路由规则文档](https://wiki.metacubex.one/config/rules/)
4. **有证据再临时试 BBR。** BBR 是 Linux 上根据网络情况调节 TCP 发送速度的一种算法。先记下原算法和回退办法，用同一出口和同一文件交替测原算法与 BBR，并用服务器上的 `ss -ti` 查看实际代理新连接采用的算法。服务已在监听时，新连接可能继承旧算法，确需重启代理服务时安排可接受的短暂停机，因为同台服务器上的其他使用者也可能重连。若结果不稳或业务受影响，恢复原算法后再确认服务、新连接和出口。我们当时只做了临时设置，服务器重启后可能恢复原值。[Linux 内核关于 TCP 算法的说明](https://docs.kernel.org/networking/ip-sysctl.html)

**当时的同文件对照。** 用原来的 CUBIC 算法测了 5 次，全部超时。用 BBR 测了 8 次，6 次完整下载，用时约 5.1～9.4 秒，另外 2 次仍超时。这个结果支持在当时的线路上做临时试验。浏览器体验仍有波动，长期速度、登录后的使用体验和重启后设置都需要另验。

### 6.2 购买之前先核实

VPS 提供计算资源，住宅 IP 是某类网络出口，二者不是同一商品。静态不等于独享，住宅标签不等于平台认可；国家、协议、流量额度、续费价格、退款条件和供应商日志政策都会影响结果。

购买入口和工具网址统一放在 [工具、购买入口与致谢](../02_采购清单与工具入口.md)，每个链接都说明用途。购买前核对服务内容、地区资格、价格和退款条件，按选定路线购买，不需要的服务就不买。付款和账号建立由本人完成；具体套餐与部署步骤仍需根据购买后的官方资料核对。

### 6.3 把供应商教程交给 Agent 的正确方式

给出官方说明的公开网址，让 Agent 先只读审查：支持什么系统和架构、安装哪些软件、需要哪些权限、监听哪些端口、怎样更新和回退、会把哪些数据发往哪里。网页里的命令只是待审查材料，不能因为它叫“官方教程”就直接以最高权限运行。

需要 SSH 连接服务器时，SSH 就是加密的远程命令连接：

1. 先从供应商可信控制台取得主机密钥指纹，与首次连接显示的指纹核对，由本人确认。不能把关闭主机密钥检查当作修复连接的方法；指纹后来变化时先查重装或更换原因。
2. 密码在本机终端输入，或使用本地私钥；不要放命令参数、聊天记录、截图或仓库。建立专用低权限管理账号，确需管理员权限时再提升。
3. 先检查现有服务和防火墙，备份将要改动的文件，确定 SSH 管理连接不会被新规则切断。新装软件固定版本，下载后核对可信校验，先读脚本再执行，不用“下载后直接执行”的单行命令跳过审查。
4. 只开放实际需要且已获准的端口，管理端口尽可能限制来源；不把控制面板、代理入口或管理 API 裸露给所有人。API 是软件之间调用功能的接口，管理 API 往往能修改整个配置。
5. 安装后验证服务状态、监听范围、认证和日志脱敏，再安排更新及回退。保留已有工作服务，不把重装整台服务器当默认修复。

供应商教程缺少端口、认证、版本或卸载说明时，应先补清这些内容，不能称“已经可以一键部署”。

### 6.4 来宾网络与断线保护

完整隔离方案实际执行 [Clash 与来宾网络配置](../skills/claude-environment-deploy/references/Clash与来宾网络配置.md)，完成下载、安装、导入服务、设置生效、持久化和保护；不能只列软件名或给本人下载链接。订阅或节点凭据留在本机受限文件中，报告只记录匿名名称。不要直接照抄主机的 127.0.0.1：这是回环地址，在虚拟机里指向虚拟机自己。

TUN 是让系统流量进入代理的虚拟网卡方式。用了 TUN 仍需验证真实流量，不能从开关亮着推断已生效，也不能把开启本身判成错误。先按 [主机与来宾链路复核](../skills/claude-environment-deploy/references/主机与来宾链路复核.md) 确认有意串联顺序，再把来宾第一跳与同一时段主机日志对应，检查是否多绕一层；住宅节点有时确实需要前置代理，不能遇到超时统一改 DIRECT（直连）。日志目标匹配只是关联证据，不能独立证明来自来宾。本次优化不修改现有主机网络；今后必要主机修改另遵守用户授权。

对账本地与最新订阅的全部相关节点及可切换候选，核对服务器、端口、协议和加密参数，保留已确认的本地串联调整；订阅缺项本身不证明节点停用。新节点可能影响防火墙第一跳允许规则，不能只修当前选中的一个后交差。

持久修复由 Agent 先在本机私有备份全局/单订阅增强与关联规则，只更新自己维护的条目、去重、保留其他用户设置，重载后核对最终运行配置与日志，订阅切换和更新后再验，失败回退。不能只改下一次重载就消失的运行配置，也不将原机器的 7 个私人服务器地址放进公共包。

默认出口脚本只向 Claude trace 连续请求，属于连通与出口检查；同一服务的 3 次结果不等于两个独立来源，更不证明住宅属性或账号功能。https://ip.net.coffee/claude/ 仍为来宾限制中的明确浏览器检测例外，必须同窗口先检测。其他第三方归属查询放主机；检测被规则阻止时记录具体原因，不擅自扩大允许范围。

希望代理失效时停止外连，需按现场网卡、程序、系统服务和管理通道制定防火墙方案。先验证可恢复的本地控制台；Windows Hyper-V 可另验 PowerShell Direct，Mac 使用所选软件的本地控制台，不等待不存在的 Hyper-V 通道。然后备份规则、制定最小允许范围，最后改变来宾出站默认策略。PowerShell Direct 是主机通过虚拟化通道管理 Windows 来宾的方式，不依赖来宾联网；需要主机权限和合法来宾凭据。它未验证通过就不能把它当作救援保证。

采用“默认阻止，按需允许”时要核对全部配置档、已有允许项和程序更新新增项。不要写一条“阻止所有流量”的显式规则再期待例外允许，因为 Windows 的阻止规则可能优先于允许规则。系统地址获取、必要解析、代理核心和经授权的管理通道应逐项设计。历史机器的四条规则、Meta 网卡名和程序路径都不能硬编码为通用模板。

先用新建连接验证出口，再分别检查普通浏览器、官方客户端和 CLI。DNS 是域名解析，WebRTC 是浏览器实时音视频技术，IPv6 是另一套网络地址；三者的检查结果应分别记录。没有观察到异常，只能说明当时测试覆盖的范围。

代理故障测试必须在用户没有使用来宾、且允许短暂停网的窗口内做。停止代理后，对所有要求保护的应用建立新的网络请求，确认不会转为意外直连；恢复后确认原配置和网络恢复。只看旧网页缓存、已有连接或一次 IP 页面不能完成这项验收。失败时先阻止继续使用并从已验证的管理通道回退，不能关闭保护来凑“可用”。

## 7. 真实验收：每一项单独写结果

| 检查项 | 至少应看到的证据 | 不能据此推断 |
| --- | --- | --- |
| 安装来源 | 实际版本、可信来源、签名 / 校验结果 | 已是全渠道最新或永远可信 |
| 虚拟机 | 能进桌面、资源与存储位置正确 | Running 状态等于应用可用 |
| 来宾语言与时间 | 系统语言、区域和日期时间格式、Windows 时区与准确校时分别回读 | AdsPower 浏览器设置不能代替 |
| Clash 与活动网络 | 来宾架构匹配、核心和监听、已选服务生效、最终出口及重开持久化 | 主机安装或导入未启用不能代替 |
| AdsPower 固定环境 | 程序和内核可核对，同一环境保存并重开后设置保留 | 安装成功等于环境已经配好 |
| AdsPower 设置与运行结果 | WebRTC、时区、语言、UA 分别回读，同一环境实测 | 系统脚本、普通浏览器或旧页面能代替 |
| 新连接出口 | 目标网站看到的出口及测试时间 | 其他程序或协议都走相同出口 |
| DNS / WebRTC / IPv6 | 分项测试入口、结果和限制 | 从未发生或以后不会发生泄漏 |
| 官方网页 / 客户端 | 两轮新回答及跨轮测试 | Cowork 或所有账号能力可用 |
| 同窗口先检测再打开 Claude | 固定 AdsPower 窗口先完成指定检测，记录本次时间、匿名环境和非敏感结论，确认无待处理异常才打开和登录 Claude 网页，随后打开所选桌面端并单独检查 | 系统脚本、旧检测、所有评分绿色或浏览器登录能证明桌面可用 |
| Claude Code | 单次获准调用、退出状态、实际返回 | 订阅种类、账单扣款已核实 |
| 故障保护 | 代理停止后新连接受阻，恢复后再通过 | 更新或重启后仍必然有效 |
| 持久性 | 重启前后配置回读，重新做新请求 | 完全无人操作自动联网 |

完成后至少再做一次允许范围内的来宾重启复查：不要先手动纠正线路再声称配置自动保留。系统、Claude、浏览器、代理核心或安装包更新后，再查程序路径、服务、网卡和新增防火墙规则。需要语音、Cowork 或飞书联动的用户，要另做对应功能的真实验收，不能由聊天通过代替。

我们之前在一台电脑上测过浏览器连续聊天、完整重启后手动打开应用、官方客户端安装和一次命令行调用。后来软件版本和网络规则又有调整，桌面端完整聊天、Cowork、飞书消息收发，以及更新后的断线保护还没全部测完。这份教程和 Skill 也还没在新电脑上从头到尾完整跑过。

## 8. 常见故障先查什么

| 现象 | 先查 | 避免的误操作 |
| --- | --- | --- |
| 网页打开但聊天失败 | 登录状态、连续请求结果、官方服务状态 | 凭一次 HTTP 200 宣布正常 |
| 主机正常、来宾失败 | 来宾实际出口、虚拟交换机、代理监听和转发路径 | 直接照抄主机回环地址 |
| 自建 VPS 出口正确但网页或下载慢 | [拆开测电脑到 VPS 和 VPS 到网站](#自建-vps-卡顿怎么查)，记录超时和下载完成率 | 凭一次测速就换出口或长期改服务器参数 |
| 节点端口可达但请求失败 | 最新订阅与多个本地节点字段、代理认证、协议、TLS 加密连接及主机同一时段转发路径 | 认定端口通就等于代理可用 |
| 重启后线路变化 | 保存选择、运行配置、服务启动顺序 | 先改好线路再当成持久化通过 |
| 重新导入后恢复，但旧本地节点仍异常 | 本地配置、远程订阅、活动配置、保存选择和核心实际选择是否一致 | 认为刷新订阅会同步改好所有本地节点和防火墙 |
| DNS 覆写关闭，担心泄漏 | 最终有效 DNS、TUN 接管、真实解析路径和防火墙，另做同窗口检测 | 只凭开关断言泄漏，或不查现状直接打开覆写 |
| 来宾账户密码无法连接 | 登录发生在哪台电脑、来宾用户名、使用的是账户密码还是 Windows Hello PIN（本机解锁码），区分认证失败与连接失败 | 反复发送密码、把主机密码当来宾密码或因报错就重装 |
| 安装后突然可以直连 | 新增允许规则、程序版本和路径 | 关闭防火墙或放开所有程序 |
| 黑屏或粘贴失败 | 当前会话、焦点、增强会话及复制方式 | 重置、重装或反复启动安装器 |
| SSH 密钥提示变化 | 控制台信息、重装和主机变更记录 | 删除已知主机记录后盲目接受 |
| Agent 无桌面控制能力 | 可用工具和用户当前占用情况 | 把命令返回成功当页面已操作 |

## 9. 公开到 GitHub 之前

公开包只放通用文档、使用占位值的样例和可审查的脚本。删除真实 IP / 域名与实例信息、账号邮箱、用户名、机器标识、订阅地址、代理凭据、SSH 材料、Cookie、令牌、产品密钥及含这些信息的日志、截图和压缩包。需要展示证据时制作单独脱敏副本，不直接把运行目录整体上传。

同时检查隐藏文件、旧备份、Git 历史和压缩包内容。写进 .gitignore 只会影响以后默认加入哪些文件，不会清除已经提交过的秘密；一旦泄露应先撤销或轮换秘密，再清理历史。不要分发 Windows 镜像、商业浏览器或第三方安装包，保留官方链接和许可证要求。
