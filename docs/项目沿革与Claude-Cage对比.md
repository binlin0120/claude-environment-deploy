## 两个方案的定位

下表按本项目 2026-11-12 提供的内容，以及 Claude-Cage 的固定提交 [`b598e2ee1c90`](https://github.com/Lee-xeo/Claude-Cage/commit/b598e2ee1c90145bd294bd9643f0196a6a96717f) 核对。它是文档与部分源码的静态比较，不是双方产品的实机性能或安全评测。

| 对比项 | claude-environment-deploy（原 virtual-pc-setup） | Claude-Cage |
| --- | --- | --- |
| 交付形式 | 教程、Agent 执行说明、5 个辅助入口及 1 个共享帮助文件 | 集成虚拟环境、浏览器、终端、编辑器等入口的桌面工作台 |
| 虚拟机路线 | Windows x64 主机使用 Hyper-V；Mac 路线使用 Fusion 等软件，来宾仍为 Windows | 当前公开说明支持 macOS、Windows、Linux 客机，受主机平台与构建版本限制；不能沿用早期截图“只有轻量 Linux”的描述 |
| 日常操作 | 在 Windows 来宾中分别使用 Clash、AdsPower 和所选 Claude 软件，由 Agent 或本人维护配置 | 在工作台中集中管理环境和工具；当前功能以具体发行版为准 |
| 浏览器环境 | 依靠 AdsPower 保存固定专用环境，同一窗口先检测再使用 Claude | 提供自己的浏览器入口和时区、语言等环境设置 |
| 出站控制 | 在 Windows 来宾内配置默认拒绝出站和最小允许规则，按实际核心、端点、网卡及版本核对 | 所核对的出站实现位于 VM 外的 hostagent，连接指定上游，不提供失败后的直连回退；联网授权由外部闸门管理 |
| 检查与持续维护 | 本地检查脚本、同窗口第三方检测及停止核心、恢复、重启等验收要求；并非持续运行的外部网关 | 内置关键检查及授权续期，检查失败、缺证据或授权到期时维持或关闭业务外网，仍有周期采样边界 |
| 当前验证边界 | 离线模拟检查通过不能代替全新电脑安装、Mac 兼容性及真实断线阻断实测 | 公开说明和源码可核对；本次没有安装、运行或实测 Cage，不能据此认定它在所有场景更可靠 |

Cage 的定位、客机支持和用户边界依据其 [固定版本 README](https://github.com/Lee-xeo/Claude-Cage/blob/b598e2ee1c90145bd294bd9643f0196a6a96717f/README.md)；检查与恢复规则见 [网络与代理文档](https://github.com/Lee-xeo/Claude-Cage/blob/b598e2ee1c90145bd294bd9643f0196a6a96717f/docs/guide/network.md)。VM 外部出站及无直连回退的源码依据为 [egress.go](https://github.com/Lee-xeo/Claude-Cage/blob/b598e2ee1c90145bd294bd9643f0196a6a96717f/internal/cage/egress.go#L24)；授权、关闭连接和到期处理见 [gate.go](https://github.com/Lee-xeo/Claude-Cage/blob/b598e2ee1c90145bd294bd9643f0196a6a96717f/internal/cage/gate.go#L58)。后续版本可能改变，比较时请重新核对。

## 对部署和验收的启发

1. **明确谁负责持续维护。** 本项目依赖 Windows 来宾规则及现场维护，静态检查不能保证规则更新后仍有效；Cage 的外部控制边界属于不同实现。
2. **重启后先观察，再修复。** 若重启后配置丢失，不能先自动修好再把结果记为“配置持久化通过”。
3. **浏览器、桌面端和命令行分别验收。** 一个进程的出口正常不能替代另一个进程。
4. **浏览器恢复旧标签页可能先发起请求。** 先打开检测页是操作流程，不是流量闸门；若需要打开前阻断，应落实实际网络控制并测试。
5. **按新版脚本判断能力。** 早期对比图提到“四个脚本”“未查询实时核心”等描述不是本次包的全部现状；本版有 5 个辅助入口和共享帮助文件，`-ReadCoreApi` 可显式启用受控只读查询。它仍不能替代故障与重启实测。

以上属于方案取舍和可验证限制，不是对任何项目的抄袭指控、稳定性保证或作者背书。
