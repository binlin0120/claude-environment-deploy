# 来源与开源复用

当前修正版10更新于 2026-11-07。基础资料核对日期：2026-10-26，下面保留各次查阅日期；上游版本和网页状态部署前仍需复核。先看已有工具怎样处理不同电脑，再决定借鉴哪些做法。仓库有很多星标或说明写得完整，不等于这套 Claude 部署已经在别人的电脑上测过。

## 不同电脑的处理方法，参考了什么

| 资料或工具 | 借鉴的做法 | 本包怎么采用 |
| --- | --- | --- |
| [微软 Hyper-V 官方仓库](https://github.com/MicrosoftDocs/Virtualization-Documentation) 与 [系统要求](https://learn.microsoft.com/en-us/virtualization/hyper-v-on-windows/reference/hyper-v-requirements) | 先查系统版本、处理器虚拟化、开机设置和资源；正确判断已经运行的 Hyper-V | 动手前先报告主机情况。仓库中的 Demos 自述只用于演示，不直接搬进部署。 |
| [HashiCorp Hyper-V 插件的镜像构建说明](https://github.com/hashicorp/packer-plugin-hyperv/blob/main/docs/builders/iso.mdx) | 镜像、内存、虚拟交换机和输出目录按本机填写，创建输出时避免覆盖原文件 | 继续使用现有 PowerShell 脚本的参数和覆盖保护，不为单机教程增加 Packer 依赖。文档里的基础例子不能直接跑，仍需补齐系统安装内容。 |
| [Ansible Windows 软件安装模块](https://github.com/ansible-collections/ansible.windows/blob/main/plugins/modules/win_package.py) 和 [重启模块](https://github.com/ansible-collections/ansible.windows/blob/main/plugins/modules/win_reboot.py) | 根据产品标识、文件和版本判断是否已装；识别需要重启的安装结果，重启后再检查 | Skill 先检查、复用已有软件，按阶段继续。只参考做法，不安装这套管理工具，也不未经许可调用其重启模块。 |
| [家庭版升级专业版：微软说明](https://support.microsoft.com/en-us/windows/upgrade-windows-home-to-windows-pro-ef34d520-e73f-3198-c525-d1a218cc2818) | 通过微软商店或适用的专业版产品密钥升级，再检查激活 | 先告知费用和可能重启，由本人处理付款和密钥；升级后复查，不把家庭版已激活等同于专业版可用。 |

这些工具提供了可以借鉴的部署方法，不能替本包证明 AdsPower、Claude 登录和网络保护都能一键完成。Windows 路线仍要求可用的 D 盘，原脚本不增加跨盘配置；Mac 用独立流程与本人确认的目录，不套用 D 盘前提。具体条件和处理步骤见 [适用电脑与操作前检查](../skills/claude-environment-deploy/references/适用电脑与操作前检查.md)。

许可也要分清：Hyper-V 插件使用 MPL-2.0；Packer 本体当前许可与插件不同，见 [Packer LICENSE](https://github.com/hashicorp/packer/blob/main/LICENSE)。Ansible Windows 集合使用 GPL-3.0-or-later。这里只参考说明和方法，没有复制这些项目的代码，也没有把它们作为安装依赖。

Mac 分支先查询了 [UTM 开源仓库](https://github.com/utmapp/UTM)，再对照 Fusion、微软、AdsPower 和 Claude 官方资料。按用户视频选 Fusion 作为优先基础路线，UTM 保留为开源备选，不复制第三方安装脚本。具体支持边界与来源见 [Mac兼容性与来源](Mac兼容性与来源.md)。
