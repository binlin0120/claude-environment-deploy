# Mac 部署流程：先验证兼容性，再使用 Claude

修订日期：2026-10-28；既有虚拟机兼容性资料核验日期：2026-10-26。Clash 官方发布包及配置依据见下方共同参考，本次修订没有进行 Mac 实机部署。

本分支供在 Mac 上部署的人或 Mac 上的 Codex 使用。默认优先复用已有可用环境；需要新建时，先考虑免费的 VMware Fusion。已有 Parallels 正式许可可以继续用，UTM 是开源备选。本分支没有新增安装器，也不承诺无人值守或全自动完成。

完整虚拟机方案依次完成：Windows 来宾系统设置 → 来宾内 Clash 与已选网络服务 → 网络和断线保护 → AdsPower 兼容性与固定环境 → 同窗口检测 → 本人登录和应用验收。必须读取并执行 [来宾 Windows 语言与时间](来宾Windows语言与时间.md)、[Clash 与来宾网络配置](Clash与来宾网络配置.md) 和 [AdsPower 配置与验收](AdsPower配置与验收.md)。不能把建好虚拟机、安装软件或写下配置要求当作已经配完。

这是一份待实机验证的流程，不是“Mac 全套已通过”的证明。Windows ARM 能模拟部分 x64 应用，不代表 AdsPower 已正式支持 Windows ARM；具体边界见 [Mac兼容性与来源](../../../docs/Mac兼容性与来源.md)。

## 1. 确认目标、芯片、目录和授权

先确认本次目标：在 Windows 虚拟机内使用 AdsPower 的 Claude 专用环境，是否还包含 Claude 桌面端；还是本人明确选择 Mac 原生 AdsPower。后一种路线不等于虚拟机隔离，不能擅自替换。

从苹果菜单进入“关于本机”，看显示的是“芯片：Apple …”还是“处理器：Intel …”。Agent 可先执行下列只读命令，只在本机核对：

```sh
uname -m
system_profiler SPHardwareDataType | awk '/Chip:|Processor Name:/ {print}'
```

`uname -m` 显示的是当前进程看到的架构。终端经 Rosetta 运行时，Apple 芯片 Mac 也可能显示 `x86_64`；Rosetta 是 Mac 为旧版 Intel 应用提供的转换机制。要结合“关于本机”或第二条命令确认实体芯片，不能只凭第一条命令选镜像。不要把硬件序列号等完整系统资料写进公开记录。

| 本机芯片 | 本流程选择的 Windows 镜像 | 不直接复用的内容 |
| --- | --- | --- |
| Apple Silicon，也就是 Apple M 系列芯片 | Windows 11 ARM64 | 原来 Intel/x64 Windows 虚拟机及其整盘镜像 |
| Intel | Windows 11 x64 | ARM64 镜像 |

Mac 没有本教程 Windows 主机中的 D 盘。请本人确认虚拟机、下载和报告的持久位置，例如本人选定的外置卷，或 `~/Documents/Codex/ClaudeVM/`。`~` 表示当前用户目录，这只是示例，不替本人决定。虚拟机内的 Windows 路径也要单独核实，不能据此认定来宾已有 D 盘。宿主机应用和必要系统组件的实际安装位置按 macOS 与安装器要求处理，不承诺指定资料目录可以消除全部系统盘写入。

操作授权、软件许可、系统激活是三回事：本人允许安装不等于取得 Windows 许可，拿到镜像不等于完成激活，已激活也不能单独证明许可来源符合实际用途。先核对已有权益和本次范围；无需一律要求先购买。遇到必须由本人接受的条款、登录、验证码或付款，交本人处理，不代填凭据、不自动下单。

## 2. 选择虚拟机软件和正式镜像

### 先找能用的文件，再决定是否联网下载

1. **已有就复用。** 先检查 Mac 上是否已有能用的 Fusion、Parallels 或 UTM，以及已装好的 Windows 虚拟机。确实缺文件时，再查本人同意访问的下载目录、移动硬盘或局域网共享，找已下载的官方 DMG（Mac 安装文件）和 Windows ISO（系统安装文件）。按下文核对文件来源、架构、许可和校验值，确认后直接安装。
2. **有校内或单位授权就先用国内正版渠道。** [中山大学微软企业服务门户](https://ms.sysu.edu.cn/win11) 列有 Windows 11 ARM64 和 x64 及校验值，下载限该校网络，按学校许可选对应版本。[上海交通大学正版软件授权中心](https://software.sjtu.edu.cn/Data/View/298) 把 ARM 版放在交大云盘的“交大空间 → 正版软件 → 微软校园软件正版化”。仅本人符合下载和使用资格时走这些渠道。
3. **缺包才短测实际下载速度。** 选下方符合所需版本的厂商入口，观察实际文件下载约 15 秒，用文件大小和速度估算多久能下完。若速度达不到本次可接受的等待时间，先暂停，换本人已有且可用的另一条网络或另一台电脑测试。哪条实际更快就用哪条下载。下完用移动硬盘或局域网拷到 Mac，再验原文件。下载器和网络都由现场条件决定，无需改系统代理、换自建 VPS 或改变虚拟机的固定公网出口。

Fusion 的国内公共镜像尚未找到可核实的渠道。无校园或单位资格的用户，可走自己已下载的原版文件、另一台电脑或另一条网络。国内官网页面能提供原版文件入口和校验资料，下载速度以实际文件为准。

### 缺文件时使用的厂商入口

- **VMware Fusion（免费参考方案）**。登录 [Broadcom 官方下载页](https://support.broadcom.com/group/ecx/productdownloads?subfamily=VMware+Fusion)，选兼容本机 macOS 的正式版 DMG（Mac 安装镜像）。入口或账号有问题可按 [Broadcom 下载指引](https://knowledge.broadcom.com/external/article/368734) 操作。
- **Parallels Desktop（付费备选）**。[Parallels 中国官网](https://www.parallels.cn/products/desktop/download/) 提供官方安装入口。已有授权时，按许可证和 macOS 选择版本。下载页列有完整安装镜像，适合需要离线安装软件的场景。
- **UTM（开源备选）**。从 [项目官方 GitHub 发行页](https://github.com/utmapp/UTM/releases/latest) 选稳定版 UTM.dmg，安装 Windows 时参考 [UTM 官方指南](https://docs.getutm.app/guides/windows/)。也可由本人选择 [中国区 Mac App Store 的官方 UTM](https://apps.apple.com/cn/app/utm-virtual-machines/id1538878817?mt=12)，商店版付费。

### Windows 架构与原版校验

- **苹果 M 系列芯片**选 [微软中国官网 Windows 11 ARM64 ISO](https://www.microsoft.com/zh-cn/software-download/windows11arm64)。ARM64 是这一类芯片对应的系统架构。没有已核验的 ISO 且实际下载速度合适时，可选 Fusion 向导里的 Get Windows 从微软下载。
- **Intel Mac** 选 [微软中国官网 Windows 11 x64 ISO](https://www.microsoft.com/zh-cn/software-download/windows11)。在页面中找 ISO 下载，安装助手是给现有 Windows 使用的。
- 下载后，在 Mac 的终端输入 `shasum -a 256 `（保留末尾空格），把 ISO 文件拖进终端，再按回车。SHA-256 就是文件的数字指纹，零售版与微软页面同版本、同语言、同架构的值逐字比对。校园批量授权版与学校门户公布的对应版本校验值比对。Fusion 的 DMG 若在 Broadcom 下载详情有 SHA-256，也按同样方法比对。安装时保留 macOS 的签名检查。

## 3. 建机并保留本地恢复入口

1. 在已授权范围安装或打开选定软件。新建虚拟机时先选第 2 节已经核验的本地 ISO。确实没有可用 ISO，且实际下载速度合适时，可在 Fusion 向导选择 Get Windows，或在 Parallels 控制中心点 ＋ → Get Windows 11 from Microsoft；具体文字以当前界面为准。
2. 选择已确认的虚拟机保存目录，创建一台专用 Windows 11 来宾；“来宾”就是虚拟机里的系统。已有对应环境时先盘点，不覆盖、不重新创建。
3. 按 Mac 实际余量分配资源。若主机有至少 16GB 内存且余量足够，可把 4 个虚拟 CPU、8GB 来宾内存和约 80–100GB 可增长虚拟磁盘作为初始试装参考；它们不是通用最低配置，也不保证性能。主机仅有 8GB 内存时，先说明主客机争用内存的限制，不承诺 AdsPower、Windows 和桌面端同时流畅。
4. 按受支持的 Windows 11 配置使用 UEFI（新版启动固件）、安全启动和虚拟 TPM；TPM 是系统用于保护密钥的安全模块。若软件要求加密才能添加 TPM，按官方界面由本人保管密码和恢复材料，不写进交付记录。不要照搬绕过检查的注册表命令。
5. 网卡先选 Shared/NAT，在 Fusion 中通常显示为 Share with my Mac，也就是借 Mac 转发上网。不要随手改成桥接到真实局域网。先关闭不需要的共享文件夹、剪贴板和拖放；需要传文件时再明确范围。
6. 在软件自己的可见控制台里安装 Windows，按当前官方提示完成初始设置和本人所需操作，不照搬视频里的激活或跳过联网命令。安装对应的 VMware Tools、Parallels Tools 或 UTM 来宾工具，再检查网卡和显示是否正常。
7. 首次进入 Windows 桌面后，由 Agent 按 [来宾 Windows 语言与时间](来宾Windows语言与时间.md) 检查并实施本次已确认的显示语言、区域和日期时间格式、时区与时间同步设置。显示语言、浏览器请求语言和时区是不同项目；按参考文件及本人已确认选择分别设置和回读，不因 Mac 主机使用中文就跳过，也不把中文或英文写成 Claude 的官方要求。需要本人选择的缺口一次说明，其余已授权操作由 Agent 完成。
8. 确认 Windows 架构、系统版本和许可状态，并在修改网络限制前创建快照或关机备份。快照是可回退的虚拟机状态，可能含本人资料，应只留在受控位置。

**必须保留 Mac 本地虚拟机控制台。** 即使 Windows 网络被阻止，仍应能从 Fusion、Parallels 或 UTM 窗口进入来宾恢复设置。Windows 上的 PowerShell Direct 是 Hyper-V 专有的主客机管理通道，不能套到 Mac。Mac 终端装有 PowerShell 也不会自动获得这一通道。

如需自动化，先发现本机实际接口；看得见窗口不等于 Agent 已有辅助功能、自动化或屏幕控制权限。可在本机只读检查：

```sh
command -v vmrun
test -x "/Applications/VMware Fusion.app/Contents/Library/vmrun"
```

第一条未输出不代表 Fusion 没装，第二条也只是检查常见位置。实际发现该文件后，可用下面命令列出运行中的虚拟机，输出只在本机查看，不公开私人路径：

```sh
"/Applications/VMware Fusion.app/Contents/Library/vmrun" -T fusion list
```

Fusion 有命令行和 REST API，也就是供程序调用的接口；具体版本能否从主机在 ARM 来宾内执行命令，要结合来宾工具和本机实际结果验证。Agent 应先读取已安装工具的帮助并检查来宾工具状态，在已有授权及安全凭据输入条件下，尝试一次不含敏感内容的来宾系统查询，确认实际能否执行；再检查现有桌面控制工具能否操作目标来宾。不能只见到接口就称可用，也不能未经尝试就笼统让本人自行设置。没有适用控制能力或权限时，写明已查工具、具体失败及最少本人操作，必要权限由本人按系统界面授予；本人完成后继续其余已授权工作。不要另造通用安装器或添加不必要控制服务；本方案必需的官方软件下载、安装和配置仍由 Agent 在授权内完成。

## 4. 在 Windows 来宾完成 Clash、代理链路和断线保护

此阶段先于依赖网络的 AdsPower 登录和浏览器兼容性检查。不能假定 Mac 上已有代理会覆盖 Windows 来宾，也不能只让本人去下载 Clash。按 [Clash 与来宾网络配置](Clash与来宾网络配置.md) 完整执行下列阶段，实际参数由目标来宾和本人已选服务确定。

1. **下载与安装由 Agent 完成。** 先检查来宾已有 Clash Verge Rev、Mihomo 核心及保护规则，可用则复用。缺少时从 [Clash Verge Rev 官方 GitHub 发布页](https://github.com/clash-verge-rev/clash-verge-rev/releases) 获取适用的稳定版 Windows 安装包，按共同参考核验来源、架构和文件。Apple 芯片的 Windows ARM64 来宾优先官方 `arm64-setup.exe`，Intel 的 x64 来宾使用官方 `x64-setup.exe`；不要因为宿主机是 Mac 就把 `.dmg` 下载给 Windows。安装文件和记录保存到已确认目录，必要系统组件及来宾 C 盘写入按已授权来宾部署范围执行；涉及新增 Mac 主机改动另说明并取得覆盖该项的授权。
2. **导入本人已选的服务并保存。** 使用本人已有且获准的订阅、节点或受控配置，通过软件原生安全输入完成；需要本人登录、验证码或输入秘密时只交给本人这一环节。订阅和代理凭据不放聊天或公开记录，不把缺少配置解释成必须购买新套餐。资料不足时准确列出所缺协议和配置项，继续已授权的独立工作。
3. **落实已选代理链路。** 按共同参考核对来宾实际的前置连接、必要中转与最终出口；若用户已选择含住宅出口的串联方案，实际配置前置连接与住宅代理的依赖关系，分别验证两段及最终新请求的出口，再保存配置与节点选择。不把节点名称、端口可达或主机检测结果当作串联成功，不为检测自行换国家地区或临时增加另一条代理。VPS 和住宅 IP 是否使用由本人既有选择及实际需求决定，不作为所有人的购买前提。
4. **落实系统流量和解析。** 按共同参考安装并验证必要的服务模式，配置 TUN（让系统流量进入虚拟网卡）、实际路由、DNS（域名解析）与 IPv6（新版网络地址）处理；读取实际生效配置及新请求结果。Shared/NAT 只表示借 Mac 转发联网，不等于代理接管；来宾 `127.0.0.1` 指来宾自己，不能填成 Mac 的代理地址。AdsPower 显式代理与系统 TUN 采用已设计的一条路径，不随意重复叠加。
5. **完整隔离方案必须配置断线保护。** 先实际确认 Mac 本地虚拟机控制台可用，备份来宾防火墙和网络设置，再按共同参考及现场地址、端口、程序、网卡和必要系统连接制作最小允许规则，最后改变来宾出站默认策略。所有适用防火墙配置档、已有允许规则和新增安装规则都要核对；不能用“显式阻止全部流量再加允许”代替设计，也不能照抄 Hyper-V 网关、管理规则或旧机网卡名。只允许实际必需路径，不能临时全放通来凑可用。明确选择 Mac 本机路线时另行设计，不把来宾规则套到 Mac。
6. **验证中断、恢复和持久化。** 在已授权的短暂停网范围内，先对已就绪的通用路径验证实际核心停止和恢复，再正常关闭重开，回读配置、节点及已确认的启动方式。全部所选应用安装完成后，把最终来宾重启与应用验收合并执行，避免不必要重复重启；不能先手动修正线路再称自动保留。分别记录实际出口、解析、规则和恢复结果，不输出真实地址或凭据。

网络阶段的检测用于确认本人合法使用路径和诊断异常，不用于绕过地区、账号或服务资格要求。某阶段未通过，暂停依赖它的使用并记录原因，继续独立已授权工作；不把未测项写成完成。涉及真实 Claude 应用的断线测试在相应应用安装后补验，通用网络请求通过不能替代应用验证。

SSH 或 WinRM 是经网络管理来宾的通道，只有实际配置、认证并限制来源和端口后才可使用；不是默认救援入口。不为管理方便开放全部主机网段，优先使用已验证的本地控制台恢复。Mac 不要求不存在的 Hyper-V PowerShell Direct。

## 5. 网络就绪后，进行 AdsPower 兼容性试装与配置

从 [AdsPower 官方下载页](https://www.adspower.com/download) 获取来宾适用包。官方目前明确列出 Mac 的 Apple Silicon/Intel 包及 Windows 32/64 位包；本次未找到 Windows ARM 的正式支持声明。Windows 64 位这一标签不能单独证明它是 ARM64 包。

在前一阶段网络就绪后，Windows ARM 先试装并检查：管理界面能否打开、本人能否正常登录、固定浏览器环境能否启动、所选浏览器内核能否加载页面，以及正常关闭重开和更新后能否继续使用。由 Agent 按 [AdsPower 配置与验收](AdsPower配置与验收.md) 完成固定环境、已选网络衔接、WebRTC（浏览器实时通信）、浏览器语言与时区及内核设置，保存并回读。Windows 系统语言与区域设置不能替代浏览器配置，程序安装成功也不等于环境已配好。

仅使用本人已选且获准的网络，不为兼容性试装随意换地区。失败时保存脱敏错误、程序和内核版本，暂停依赖它的步骤；不要称为完整支持，也不要反复重建环境或清空登录。

用户可以另行选择在 macOS 直接安装原生 AdsPower 与适用的 Clash `.dmg`。那是另一条路线，Windows 来宾防火墙不会保护 Mac 原生进程，原来的隔离和断线保护结论全部要重新核对。未经本人选择，不静默改走原生路线，也不默认购买 Parallels 解决未知兼容性。

## 6. 同一个 AdsPower 窗口，先检测 IP 再打开 Claude

1. 在目标系统的 AdsPower 管理界面复用或创建一次固定专用环境，保存后从管理界面启动，确认实际窗口确实对应它。
   新建环境不把 Claude 设为自动启动网址。复用环境若自动恢复已有 Claude 标签，可能在检测前已发请求；先说明这一限制，在获准范围内调整启动行为，不擅自退出账号或清空会话，不声称检测前绝无 Claude 请求。
2. **必须在这个同一实际窗口先打开 https://ip.net.coffee/claude/。** 等待本次检测完成，由本机界面核对当前 IP（网站看到的网络出口地址）、国家地区、网络属性，以及可见的 DNS、WebRTC、时区等结果是否与预期一致。DNS 是网址解析，WebRTC 是可能使用不同连接的浏览器实时通信功能。
3. 关键出口结果缺失、检测失败或存在待处理异常时，暂停依赖它的 Claude 打开和使用，写清卡点；其他独立且已授权的工作继续。不要求所有评分绿色，也不把没有结果当成没有泄漏。
4. 先具体尝试已具备且适用的来宾执行和桌面控制工具；确实不能控制或辨认这个窗口时，记录工具缺口，明确交代本人从哪个环境打开该网址、核对哪些项目，只交回最少操作并请本人反馈非敏感结论。不能改用另一个浏览器或远端抓取来代替。
5. 本次结果与预期一致且无待处理异常后，才在同一窗口打开官方 Claude 网页，由本人登录。已登录的复用原会话，不退出重登、不导入 Cookie。

公开网页抓取反映的是抓取服务自己的出口，不是客户 Mac、Windows 来宾或 AdsPower 窗口的 IP。本轮读取检测网站也不代表任何一台客户电脑已通过。记录只保存检测时间、匿名环境代号和非敏感结果，不写真实 IP、凭据或带真实地址的截图。

检测页是第三方网站，会收到请求和网络信息；它不能证明账号资格或聊天可用。详细限制和已核对的数据发送行为见 [使用前检测与可选防护](使用前检测与可选防护.md)。不要在检测页输入密码、验证码或授权链接。本人不同意使用此页时，先停在这个依赖步骤，说明原因，不能由执行者自行换方法并声称完成原要求。

## 7. 浏览器、桌面和断线分别验收

| 项目 | 实际要做的验证 | 通过边界 |
| --- | --- | --- |
| 来宾系统语言与时间 | 回读已确认的显示语言、区域和日期时间格式、时区及时间同步；需要注销或来宾重启的设置完成后再复查 | 系统设置与浏览器语言、时区分别记录；没有统一语言或时间格式能证明 Claude 可用 |
| Clash 与已选链路 | 回读安装架构、实际核心和配置，验证 TUN、DNS、路由、最终出口及已选串联关系，正常关闭重开后复查 | 官方安装包存在、端口可达或节点名称不能证明完整链路通过 |
| AdsPower 设置保存 | 正常关闭并重开同一环境 | 窗口、配置和内核可用；不新建环境代替 |
| 网页连续对话 | 指定检测完成后，在同一窗口做两轮不含隐私的新对话，第二轮承接第一轮 | 两轮都获得实际回答；旧页面或首轮成功不够 |
| 桌面端，仅本次包含时 | 从 [Claude 官方下载页](https://claude.ai/download) 选择相应安装包；Windows ARM 优先官方 ARM64 包，由本人按当前官方流程登录，然后独立做两轮新对话 | 单独确认桌面网络及所需功能；不假定继承 AdsPower 代理、指纹或登录 |
| 代理核心中断及恢复，完整隔离方案必做 | 先确认恢复控制台及已获准的短暂停网范围，再停止实际代理核心；浏览器和所选桌面分别发起新请求，确认没有违规直连；恢复后重测 | 关闭代理窗口不等于核心已停止；只杀 Claude 进程不能证明网络被阻止；另选本机路线按其实际保护范围记录 |
| 来宾重启 | 不先手动修正，回读系统语言时间、Clash 启动及节点选择、TUN/DNS/路由和防火墙设置，重开原环境，重新完成指定检测，再验证网页与所选桌面 | 不据此推断 Mac 主机重启也通过；不为验收新增自动登录或保存登录凭据 |
| 更新后 | AdsPower、浏览器内核、代理、虚拟机软件或系统更新后，重查设置、指定检测、对话及保护 | 旧版本结果不能覆盖新版本 |

重开环境、网络恢复、来宾重启和相关更新后，都在同一 AdsPower 窗口重新检测，再打开或继续使用 Claude。检测异常时暂停依赖步骤，不沿用旧结果。

桌面端安装包提供 ARM64 不等于所有功能在虚拟机里都可用；需要嵌套虚拟化的功能尤其要另查支持范围。嵌套虚拟化是“虚拟机里再运行虚拟机”。桌面官方登录如唤起系统浏览器，由本人按实际流程操作；不要强制把授权链接搬进 AdsPower，不修改回调参数，也不记录敏感授权网址。

每项分别写“已验证”“待本人操作”“失败及原因”或“不适用”，附版本和证据范围。本流程没有 Mac 实机记录，不能预先把任何项目标成已通过。
