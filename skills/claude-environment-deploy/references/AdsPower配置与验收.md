# AdsPower 固定环境配置与验收

本分支用于包含 AdsPower 的已选路线。Windows 主机完整方案在 Hyper-V 专用来宾里执行；Mac 用 Fusion／已选软件的 Windows 来宾，先完成 [Mac 部署流程](Mac部署流程.md) 中的架构与 AdsPower 兼容性核对，Windows ARM 不据安装成功推断厂商支持。用户另行明确选择本机＋AdsPower 时，在本机执行并标明不是虚拟机隔离方案。用户明确选择普通浏览器时，不因此安装 AdsPower、套餐或服务器，也不将该结果称为完整方案。

AdsPower 是提供独立浏览器配置的指纹浏览器。它在本方案中的作用是固定专用环境；不能据此承诺账号安全、绕过官方资格或改变实际所在地。网页和桌面客户端仍分别验收。

## 原机方法如何复用

原机已有历史证据的是：WebRTC 禁用；时区与语言按已选出口关联；当时浏览器语言及请求语言为 en-US,en，中文阅读使用 zh-CN 网页翻译。复现同一已选美国出口方案时，由 Agent 在当前版本实际设置、保存并重开回读这些项目，不能只给本人一张核对表。用户明确另选环境时按其目标执行，不为凑历史值改国家或指纹。

这是浏览器层，Windows 系统的显示语言、日期时间格式和实际时钟另按 [来宾Windows语言与时间](来宾Windows语言与时间.md) 实施；代理先按 [Clash与来宾网络配置](Clash与来宾网络配置.md) 完成。浏览器请求语言为英文不表示 Windows 必须全英文，网页翻译不应改掉请求语言。原 Windows 系统确切值没有完整依据，不声称已复制。

## 1. 先确认范围和操作能力

执行顺序为：网络与 profile 检查 → 保存并打开目标 AdsPower 环境 → 必须在同一窗口先打开 https://ip.net.coffee/claude/，完成本次检测并确认无待处理异常 → 才打开 Claude 网页并由本人登录 → 仅在本次包含桌面客户端时，再打开它并单独验收。profile 指一份独立浏览器配置及其会话。

先读本次阶段记录，确认目标电脑、已有 AdsPower、现有 profile 和用户选定的产品。目标电脑在完整方案中指来宾，在本机＋AdsPower 路线中指主机。具备相应控制工具时，本人主要处理登录、验证码、付款、身份核验和授权确认，其余已获准的下载、设置、启动、检查与记录由 Agent 执行。工具不足时，明确列出本人需要完成的点击操作，以及 Agent 未能独立验证的项目。

先确认正在检查哪台系统：本参考主要面向 Windows 来宾；若本人另选 Mac 原生 AdsPower，应按当前 macOS 界面与专用网络方案实施，不能宣称拥有 Windows 来宾隔离。主机上安装 AdsPower，不代表来宾里也已安装；完整方案需要检查目标来宾自身的安装和环境。不要通过共享主机浏览器资料、复制 Cookie 或账号目录来代替来宾配置。现有版本号只用于盘点，不写死为某个截图里的版本。

按观察到的状态继续，而不是只分“装了／没装”：

| 现场情况 | 下一步 | 此时不能声称 |
| --- | --- | --- |
| 目标电脑未安装 | 核对官方来源，在已授权范围安装 | 主机已装就代表来宾也有 |
| 目标电脑已装，但没登录管理软件 | 复用安装，交本人登录 AdsPower | 安装完成等于已登录 Claude |
| 已登录 AdsPower，但没有 Claude 专用环境 | 按当前版本界面创建一次并配置保存 | 不用重装就无需配置 |
| 已有对应专用环境 | 核对用途、设置和网络后复用 | 随便打开一个环境就算对 |
| 指定环境已启动 | 确认窗口来自目标电脑的该环境，先在同一窗口完成指定检测，确认无待处理异常后才打开 Claude | 网址正确、软件已启动或旧检测结果就证明本次通过 |
| 工具无法控制或辨认该窗口 | 改用可用的界面工具；仍做不到则给本人明确点击步骤 | 改用工具自带 Edge／Chrome 后算完成 |

确认工具确实能操作目标电脑和该 AdsPower 窗口。其他浏览器工具打开的独立浏览器不等于这个 profile；无法辨认实际窗口、缺桌面控制或权限时，列出具体停点和所需本人动作，不以文字冒充操作。

确认窗口时，从目标电脑中的 AdsPower 管理界面启动指定环境，结合环境的开启状态与实际出现的窗口对应检查。若经已授权的官方接口启动，应核对启动结果确实对应同一个环境；启动成功不等于页面或登录成功。不能仅凭图标、窗口标题或 claude.ai 网址判断浏览器身份，不在报告中保存实际环境标识或会话信息。

运行记录只保存匿名环境代号、版本、非敏感设置及结果。不要读取、导出或复制 Cookie、会话数据库、密码、令牌、代理完整配置；不要将真实 profile 标识、账号和授权网址放进报告、截图或仓库。

## 2. 核对来源、安装和本人登录

1. 检查目标电脑中现有 AdsPower 的来源、程序版本及浏览器内核版本，已可用则复用。需要安装时，从 [AdsPower 官网](https://www.adspower.com/) 进入当前官方下载和帮助文档，核对适用系统、发行方、版本及可信校验，不分发第三方重打包或商业安装包。
2. Windows 主机路线的下载、报告及备份按主 Skill 的 D:\Codex 约定执行；Mac 按已确认的 Mac 任务目录执行。Windows Hyper-V 路线的来宾 C 盘存于主机 D 盘虚拟硬盘内；Mac 来宾 C 盘存于本人确认目录内、由所选软件管理的虚拟磁盘中。按已授权来宾部署范围使用；需要新增主机系统写入时另按既有边界处理。
3. Agent 安装并打开 AdsPower，到其原生登录界面后交给本人完成登录、验证码及必要条款确认。完成后只确认应用可用，不查看凭据；没有需要付费的明确同意就不升级、不下单。
4. 优先使用已有桌面控制工具。历史免费环境的 Local API（本机程序控制接口）曾不可用，这不是当前所有套餐的定论；部署时核对当期官方文档和实际账号能力。
5. 仅当接口确实可用、用户授权且当前工具适配时，才选官方接口；密钥留在本机安全输入或受控配置中，不打印响应里的敏感字段。接口受限时改用界面控制，不默认购买套餐或添加额外 MCP（供 Agent 调用外部功能的工具服务）。

## 3. 复用固定 profile

首次新建环境不把 Claude 设为自动启动网址，先完成指定检测。复用环境如自动恢复已有 Claude 标签，可能在检测前已发请求；保留用户数据、先说明此限制，不声称实现了检测前零请求。需要调整启动或恢复设置时，先说明具体改动并在授权范围内执行，不自行清空或退出会话。

先在界面识别用户指定的既有环境，结合匿名用途和当前窗口确认。已有对应 profile 就打开它；没有时仅创建一次专用环境，保存后始终复用。不得因网络、登录或授权失败反复重建、重置、随机更换指纹或清空会话。

新环境使用当前官方文档与实际界面支持的设置，不编造按钮名或沿用已失效字段。未选定的 Canvas、WebGL 等绘图与图形设置保持产品默认，记录“默认，未单独调整”，不声称已核实这些选项的效果。

不要从其他电脑导入登录资料或复用 Cookie。配置备份若包含会话信息，只能留在本人原有受控位置，不读取其内容，不混入公开交付。关闭环境前正常保存并退出，不能靠强杀进程证明设置保存。

## 4. 明确该 profile 的真实网络路径

先核对目标电脑中已选择且获准的网络。需要代理时，选择一条有依据的路径：profile 显式使用该电脑内实际监听的代理；或 profile 按当前官方方式使用该电脑系统网络，由已经验证的 TUN 虚拟网卡接管。本机路线已有正常网络且没有选代理时，不因此新增代理；不要未经设计叠加两套代理。

127.0.0.1 是回环地址，指正在使用它的那台电脑自己；来宾中指来宾，主机中指主机。不能跨系统照抄地址、端口或路由。只有确认代理在目标电脑内监听且协议匹配时才填其实际值；账号和密码只在本机原生输入中使用。

若使用 TUN，核对目标电脑路由和解析，完整隔离路线另核对来宾默认拒绝出站规则；开关亮着不等于流量已接管。本机路线不能未经授权套用来宾防火墙策略。若使用 profile 显式代理，也要检查浏览器的解析、WebRTC 和 IPv6 是否存在旁路，不能用“代理检测成功”代替。

在打开 Claude 网页及本人登录之前，必须先保存并从管理界面打开这个 profile，在确认对应的同一实际窗口打开 https://ip.net.coffee/claude/，等待本次检测完成。在本机目视核对当前 IP（网站看到的网络出口地址）、国家地区、网络属性，以及 DNS（域名解析）、WebRTC（浏览器实时通信）、时区等可见结果，确认与预期相符且无待处理异常，才进入 Claude 网页步骤。系统脚本只覆盖其自身请求，不能代替该浏览器结果；两者不一致时先定位路径，不凭节点名称宣布成功。

关键出口结果缺失、检测页打不开或超时、有待处理异常，或无法控制和确认目标窗口时，暂停依赖它的 Claude 打开与使用步骤，写清卡点及本人需要从哪里打开网址、核对哪些结果。不静默跳过，不换普通浏览器，不自行改用其他检测方式，其他独立且已获授权的工作继续。DNS 或 WebRTC 无结果不等于无泄漏，须说明覆盖限制并核对原因；不要求所有评分绿色。只记录本次检测时间、匿名环境代号、检测完成状态和非敏感结论，不保存真实 IP 或带真实地址的截图。具体限制见 [使用前检测与可选防护](使用前检测与可选防护.md)。

### 非敏感设置核对表

| 项目 | 设置页需要核对 | 同一 profile 的运行时检查 | 可记录内容 |
| --- | --- | --- | --- |
| 环境复用 | 已有环境或本次仅创建一次 | 打开的是指定窗口，重开仍为它 | 匿名代号、复用或新建结果 |
| 代理链路 | 已选的一条路径与实际监听相符 | 新请求出口与既定路径相符 | 路径类型、国家和状态，不存公网 IP |
| WebRTC | 根据当前字段核对实际策略 | 检查实时通信的候选网络结果和测试范围 | 设置值、是否观察到未获准网络路径 |
| 时区 | 核对按 IP 关联或当前支持的等效选项 | 浏览器运行时报告的实际时区 | 实际时区及与预期是否相符 |
| 语言 | 核对按 IP 关联或当前支持的等效选项 | 浏览器语言及请求语言分别检查 | 实际语言及一致性结果 |
| UA 与内核 | 核对浏览器标识和所选内核 | 查看浏览器实际版本与 UA 主版本 | 程序、内核和 UA 版本 |
| DNS / IPv6 | 核对当前支持的相关选项和目标电脑中适用的网络规则 | 分项测试解析与新版网络地址可达范围 | 测试入口、结果和限制 |
| 其他指纹 | 未核实项目保留默认 | 不凭默认设置推断已复现历史原机 | 默认、未核实 |

设置页值和运行时结果是两份证据，分别记录。WebRTC 的相关 API 仍存在，不等于禁用失败；反过来，仅看到“禁用”也不能证明无旁路，要看实际网络候选与测试结果。

按当前版本核对 WebRTC 禁用设置，再检查实际网络候选；相关 API 仍存在不等于暴露地址。时区和语言可按已选网络环境关联，再在浏览器运行时回读，不给所有人写死同一地区、时区或语言。

UA 是浏览器向网站自报的版本信息，应与实际所选内核合理一致；版本补丁号不要求逐位相同，不把某个旧版本固定成安装要求。不要为凑相同数字随意改写浏览器标识。

需要中文阅读时使用网页翻译或产品已有的界面语言功能，并回读请求语言确认未变化；不能把“翻译成中文”直接改成浏览器请求语言，否则会改变已选环境设置。没有验证就记录未验证。

## 5. 同窗口检测完成后，再打开和登录 Claude 网页

网络、profile 及第 4 节指定检测页的本次检查完成，确认与预期相符、无待处理异常后，才在这个已确认的 AdsPower 窗口打开官方 Claude 网页。本人完成账号、验证码及身份核验；不读取登录存储，不复制 Cookie，不用其他浏览器的检测或登录结果代替。

若发现 Claude 开在普通浏览器，只能记录“在另一个浏览器中打开，指定环境步骤未完成”。保留原标签页、账号与数据，不擅自退出、清空或迁移；回到指定 AdsPower 环境完成本步骤。本人明确改变浏览器选择时，更新范围并解释原完整方案哪些项目不再适用。

页面提示模型繁忙、容量不足或稍后重试时，保留脱敏错误，在同一环境处理；这类错误不能单独证明浏览器用错，也不是重建环境、清空登录或改用另一浏览器的理由。

在同一环境做两轮不含隐私的新对话，第二轮承接第一轮，分别观察实际回答与错误。关闭并正常重新打开同一 profile 后，先在同一窗口重新完成第 4 节指定检测，确认无待处理异常，再进入 Claude 网页并发起新请求；不能沿用旧检测结果或靠旧页面缓存当作联网成功。已登录的不必退出重登。

若当前本人还未登录，记录 pending；页面或账号错误记录实际现象和依赖，先排查，不重建环境。两轮未完成就不能将网页可用阶段写成 done。

## 6. 再打开 Claude 桌面端

仅在本次范围包含桌面客户端时执行；其安装按主流程核对官方来源和已安装版本。在上述 AdsPower 环境完成 Claude 网页登录后，再打开 Claude 桌面端，观察它当前是否已登录、是否要求本人授权，以及所选功能能否使用。

若桌面端要求登录或授权，按该版本当前官方流程，由本人在本机完成并回到发起流程的桌面进程。不要额外要求把授权链接放进 AdsPower；那不是本路线的必需条件。保持当次完整流程，不改回调、state 等用于关联本次请求的参数，不拿过期或另一进程的授权页替代。

授权网址可能含敏感参数，不写入聊天、报告、文件或截图。若当前工具会记录敏感网址，改由本人在本机直接操作，不复制到聊天；不能读取、导出 Cookie 来“同步登录”。

若官方流程唤起系统默认浏览器，按实际窗口处理并如实记录，不能声称授权来自 AdsPower。不要擅自全局修改默认浏览器或链接关联；当前官方登录流程无法完成时，说明实际停点，不为强制切进 AdsPower 额外修改系统。

回到原桌面进程检查实际登录状态、当前功能及两轮新对话。AdsPower 网页登录成功不代表桌面自动登录；即使桌面已登录或授权成功，也不能证明它继承了 AdsPower 指纹、请求语言、代理或其他网络行为。

桌面网络要单独验证。本人完成需要的操作后 Agent 继续其余已获准检查；网页两轮、桌面登录或授权、桌面两轮分别记状态。桌面原已登录时记录实际状态，不强迫重新授权；桌面未选则标记不适用，不擅自安装。

## 7. 分层验收与持续使用

| 检查项 | 必须观察到的结果 | 不得替代或扩大 |
| --- | --- | --- |
| 安装位置与实际窗口 | AdsPower 位于选定的主机或来宾；启动及 Claude 页面可对应到指定环境 | 主机有软件、网址正确或工具可控制某个浏览器不能代替 |
| profile 配置保存 | 正常关闭重开后仍是原环境与已选设置 | 程序启动不等于保存成功 |
| Claude 网页前的指定检测 | 同一目标窗口先完成 https://ip.net.coffee/claude/ 本次检查，当前出口、地区、网络属性及可见结果与预期一致且无待处理异常 | 只记录时间、匿名环境和非敏感结论；系统脚本、旧结果、无结果或全绿评分不能代替 |
| 浏览器新连接出口 | 该 profile 新请求国家与路径符合预期 | 系统脚本或宿主机结果不能代替 |
| DNS / WebRTC / IPv6 | 分项入口、实际结果和覆盖限制 | 设置页和 API 是否存在不能单独定论 |
| 时区、语言、UA | 设置页与运行时分别检查，版本合理一致 | 不硬编码历史地区、语言、153 或补丁号 |
| 网页本人登录与两轮 | 同一 profile、官方页面、两次连续新回答 | 其他浏览器及桌面结果不能代替 |
| 重开同 profile | 原环境保存，重新打开后先完成本次指定检测，再验证 Claude 新请求和网页 | 不新建环境，不靠旧检测或旧缓存 |
| 桌面登录状态及必要授权 | 网页登录后再打开桌面；原已登录则核对，需授权则本人按官方流程完成 | 不要求授权链接进入 AdsPower，不推断自动带登录 |
| 桌面独立两轮 | 桌面内两轮新回答及独立网络结果 | AdsPower 网页成功不能代替 |

中断测试须在获准的短暂停网时段进行，并先确认可恢复控制台；停止代理核心，不只是关界面。浏览器和桌面分别建立新请求，失败就记录并修正规则，不关闭保护来凑可用。

恢复与更新仍复用原 profile。重开环境、恢复网络、来宾重启或更新后，在同一窗口重新完成第 4 节指定检测，确认无待处理异常再继续 Claude；没有完成时停在相应依赖步骤，不以旧状态替代。需要改动网络或环境设置时保存非敏感变更记录并复验，不在用户未决定时扩大到新地区、新账号或付费套餐；没有工具完成的检查写具体缺口。
