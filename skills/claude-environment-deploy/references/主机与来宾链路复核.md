# 主机与来宾链路复核

修正版9，更新于 2026-10-31。本节把近期修复中有用的排查方法纳入部署流程，不附原机器私人配置、服务器、端口或日志。主机和来宾分别检查；本版辅助脚本只读，不修改现有主机网络。

## 1. 先确认想让流量走哪里

先从用户已选方案和当前受控配置确认预期链路，不要求用户重复已经确定的选择。常见情况有：

- 来宾应用 → 来宾 mihomo → 可以直接连接的最终节点 → 网站。
- 来宾应用 → 来宾 mihomo → 已选前置节点 → 最终节点 → 网站。此时 dialer-proxy（用另一个节点连接当前节点）是有意的串联。
- 主机 TUN（接管系统流量的虚拟网卡）也会看到来宾的某些外连：它可能直连第一跳，也可能再转给主机代理。是否多绕一层，要对照预期链路及当前证据。

主机开着 TUN 本身不是故障；DIRECT（直连）不是通用答案。有些节点必须借助前置代理，盲目改直连会断网。主机能正常上网不能证明来宾正常，TCP 端口能连接也不能证明加密握手、认证和最终请求成功。

## 2. 来宾先采集本次第一跳

在目标 Windows 来宾核对当前活动配置、客户端保存选择和核心当次选择，确认物理虚拟网卡实际连接的第一跳地址、端口和协议。第一跳可能是前置节点，不能用网站看到的最终出口地址代替。按《来宾网络一致性检查》对账所选链路与可切换候选节点、订阅来源和采集时间。

由 Agent 在发起受控新请求、采集连接之前先取 UTC（协调世界时），记作本轮观察开始时间；随后采集核心连接与主机日志并对齐时间。guest_checked_at_utc 不能填检查完成时间，否则请求期间的日志会被范围过滤，结果只能未知。真实地址与节点名称只留本机私有证据，不进入本包、聊天、截图或公开报告；公开结果只记匿名第一跳序号、时段、匹配数量、策略是否符合预期和限制。

## 3. 主机只读运行与私有证据

由 Agent 核对实际脚本路径后，在实际 Windows 主机执行；不能在来宾跑出结果后当作主机证据。路径变量由 Agent 按已存在的本机文件赋值：

    & $HostPathScriptPath -EvidencePath $PrivateHostEvidencePath

必要时明确启用已经配置好的主机核心本机接口只读查询：

    & $HostPathScriptPath -EvidencePath $PrivateHostEvidencePath -ReadCoreApi

脚本不新增接口、不改变监听、密钥、代理选择或网络，也不自动刷新订阅。Read-ClaudeCoreApi.ps1 只是共享帮助文件，不单独部署。没有对应权限、文件、解析器或当前日志时，相关项保持 unknown（未知），不为了检测打开远程控制接口。

私有 JSON（结构化文本）字段如下；不要把带真实值的例子放进公共包：

| 字段 | 含义 |
| --- | --- |
| guest_checked_at_utc | 本轮观察开始时间，在请求/连接采集前取值，必须含 Z 或明确时区；应在最近 10 分钟内 |
| guest_first_hops | 第一跳数组，每项含 addresses 具体 IP 地址数组、port 端口、expected_host_policy 预期主机策略；预期可为 DIRECT 或用户有意选择的明确主机组名 |
| host_log_directory | 当前主机核心实际日志目录，本机绝对路径 |
| host_active_config_path | 当前主机核心活动配置，本机绝对路径；启用 API 查询时受控取得既有接口信息 |
| host_core_path | 当前主机实际 mihomo 核心完整路径，用于核对运行对象 |

脚本只读最近 5 份日志、每份末尾 4000 行，只关联来宾采集时刻之后且最近 10 分钟的目标 IP 与端口、时间和策略。日志格式不受支持、时区不明、没有匹配或输入过期时，保留未知；不回显目标、路径、节点名或原始日志。

## 4. 关联结果怎么理解

expected_host_policy 与日志观察一致只记 snapshot_match（本次关联快照一致）；发现不同策略或拨号错误记 review_required（需要复核），无新鲜证据记 unknown。整体保持 review_required，guest_identity_proven 始终为 false。

原因是 NAT（多个设备共享对外地址）与 TUN 转发后，单凭目标服务器和端口不能独立证明这条连接来自指定来宾，主机自己的请求也可能命中同一目标。需要结合来宾新请求、时间、当前核心连接及必要的本机连接记录进一步确认。日志写着 DIRECT 证明当时选了直连策略，不能单独证明请求最终成功。不要拿大量历史 DIRECT 行数当作当前来宾功能通过。

## 5. 有证据后再做最小持久修改

本节不预授权主机网络修改。用户要求只读或明确不改主机网络时，停在具体差异、原因、拟修改内容及回退方案；继续可独立完成的来宾检查。已有授权确实覆盖该主机修改时，Agent 继续完成，不重复索取同一授权：

1. 确认修改对象是主机还是来宾、全局还是单订阅，并核对生效版本。把现有全局脚本/合并配置、单订阅增强、订阅管理设置及关联规则私有备份，记录完整原位置、摘要、匿名用途和恢复顺序。保留用户原内容，备份不进入公开包。
2. 依据当次服务和有意链路生成所需条目。仅维护自己明确拥有的条目，新增前检查等价项并去重；不清空用户规则、不整段替换 proxies（节点列表），也不把原机器的 7 个私人服务器 IP 写进部署包。已有直连规则可能有其他用途，不自动删除。
3. 使用当前 Clash Verge Rev 官方支持的全局脚本、合并配置或单订阅增强入口持久化。适用于所有已选订阅的条目才放全局；只适用单份订阅的条目留该订阅。不要只改会重新生成的活动运行文件。
4. 先校验语法与最终合并结果，再按授权重载。回读最终活动配置、核心当前选择、来宾第一跳最小允许规则和主机实际转发日志；用新请求验证最终出口，保留首次结果。不能先人工纠正再把重开或重启写成自动保持。
5. 分别测试订阅更新与切换到确实获准的另一订阅，再回到原订阅，重新核对相同状态及日志。不能只凭增强文件仍存在就称规则有效；切换导致名称、地址或端口变化，要重新对账全部相关节点与规则。
6. 发生语法、启动、出口或转发回归时，停止依赖该链路的应用验证，恢复此次改过的对应增强/规则和原选择，重载并按同样顺序复验。不要以关闭防火墙、关闭 TLS 校验或全放通来凑“恢复”。

来宾停止核心、恢复与重启测试仍按原流程，主机重启独立遵守授权。只测登录后手动开启应用，就只报告这个范围，不能称无人值守启动已通过。

## 6. 检测目标与隐私

https://ip.net.coffee/claude/ 是来宾访问限制中的明确浏览器检测例外，保留同一目标 AdsPower 窗口先完成本次检测，再打开 Claude 的顺序。Claude /cdn-cgi/trace 请求只验证连通与出口；同一服务连续 3 次请求不是双独立来源，不证明住宅属性、登录或对话。其他第三方归属查询放主机，不静默给来宾增加公网允许项。
